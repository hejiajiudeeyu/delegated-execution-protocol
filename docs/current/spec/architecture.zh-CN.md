## 0. 这份文档是什么，不是什么

**是**：为什么这个系统长这样，以及哪些性质不允许被某次实现改掉。

**不是**：字段表、端点清单、错误码表。这些会变，抄进来就会烂。上一版架构文档从 2026-04-01 起再没更新，而它抄了一整套合约字段和结果包字段——到 2026-08 时，它对 `service_tier`、`execution_budget_s`、`acceptance_window_s`、`delivery_integrity`、结算与信任分级的提及次数全部是零，也就是说，声称定义系统不变量的文档，成文早于这个系统现在赖以运转的整个合约模型。它还把若干早已不存在的路径列为真相源。

所以本版只写不变量，细节一律指向真相源。

## 1. 范围与原则

### 1.1 目标

让一个 Agent 能够可靠地把一件事委托给**不在它信任边界内**的执行方，并且事后能判断这件事到底有没有按约定做成。

「远程」指的是**执行边界与信任边界**，不是物理距离。单机 `L0`、局域网 `L2`、外部通道 `L3` 都是本协议的有效运行模式。

当前形态是**单 Operator 自托管的私有能力网络**：一个 operator 运营一张网，自己审批接入其中的责任方与热线。协议不假设存在公开市场、评分或推荐体系。

### 1.2 非目标

- 不保证实时低延迟通道（默认异步通信模型）
- 不做与闭环无关的外围业务系统
- 不做主观评价驱动的展示、打分或推荐

### 1.3 不变量

以下性质任何一次实现都不得改变：

1. **合约优先**：所有交互可落地为结构化 JSON。
2. **合约跟随 worker**：一条热线的声明由执行它的程序给出。平台不猜、不补、不用模板填空——缺就是缺（见 §3）。
3. **幂等优先**：`request_id` 贯穿全链路。
4. **最小信任**：短期 token + 结果签名，平台不托管长期密钥。
5. **可迁移**：传输通道通过 `TransportAdapter` 抽象，与业务状态机解耦。
6. **模式解耦**：`L0`–`L3` 的差异只体现在 controller 之间的通信拓扑与运行边界，**不得**改变协议语义、请求/结果结构、状态机迁移规则与幂等规则。
7. **本地控制面最小暴露**：console 前端不直接持有长期 API key，敏感能力经由本地 session、加密密钥库与 gateway/supervisor 代理访问。

## 2. 角色与边界

- **Caller**：发起委托的一方。只处理输入与输出，不承载执行方的依赖。
- **Responder**：执行方设备。持有 worker、签名私钥，向平台声明它提供哪些热线。
- **Platform**：最小控制面——目录、token、投递元数据、事件、指标。它**不执行**任何任务。
- **Transport Adapter**：Caller 与 Responder 之间的通道实现（本地 relay、邮件等）。
- **Operator**：审批责任方与热线的人。审批是本协议中唯一由人做出的判断。

信任边界落在 Caller 与 Responder 之间。平台是双方都不完全信任的第三方，因此它既不持有长期密钥，也不代替任何一方声明事实。

## 3. 热线与热线版本

一条**热线**是一个本地程序，加上一份**合约**：它接受什么、返回什么、不适合做什么、需要多久、收多少钱。

### 3.1 声明由 worker 给出

平台曾经用模板补全缺失的 schema，结果把一个 PDF 解析器对外描述成了文本摘要器。现在它不猜了：没有声明就是 `contract_declared: false`。

因此**沉默必须与回答可区分**。进程适配器的 worker 用 `--contract` 回答时必须带 `contract_version`——一个不实现该开关的 worker 也会打印出合法 JSON（它以为你在派活），没有这个正向信号就会被误认成声明。

### 3.2 版本由摘要冻结

审批冻结一个**热线版本**：一组契约字段的规范化内容，以及它们的内容摘要。`HOTLINE_VERSION_CONTRACT_FIELDS`（`packages/contracts/src/call-state.js`）是这组字段的唯一清单。

两条由此推出的规则：

- **重新提交由摘要决定**。哈希不变的重新提交保留原有批准；任何移动摘要的改动（包括改显示名）重新进入审核。对某字段的沉默是延续，不是清空。
- **默认值在读取时解析，永不写入记录**。给一条已存在的版本记录补写默认值会改变它的内容，于是已经绑定到该版本的调用会开始报 `digest_mismatch`。这也是往清单里新增字段是摘要安全的原因。

### 3.3 声明必须抵达目录

这是本仓库反复出错的地方，值得写成不变量。

声明要走完：**worker → 注册草稿 → 提交体 → 冻结的版本 → 公开目录**。任何一环丢掉一个字段，都不会报错——目录看起来是完整的，只是上面某一条是错的。已经发生过四次：文件附件声明被写死为 null；价格同意必须指名的两个字段在目录投影里丢失；worker 声明的服务档位被猜测出的默认值覆盖；修好之后又在草稿层和提交体里被丢掉一次，且是在生产上的收费热线。

因此：**任何契约字段都必须有人证明它走完了全程**，而不是靠每个新增字段的作者记得四个调用点。四仓的 `tools/contract-conformance.mjs` 以协议自己的字段清单驱动这条断言——清单里新增一个名字，检查立刻失败，直到有人把它归类为「已证明搬运」「worker 不该决定」或「今天证明不了」。

## 4. 服务条款与两个时钟

一条热线声明它的**服务档位** `service_tier`，档位同时决定两件事：

- **验收窗** `acceptance_window_s`：调用方有多久来验收
- **执行预算** `execution_budget_s`：平台按多长时间判定这次执行

这两个数是系统里所有时钟的来源。冷启动的模型可能需要几分钟；需要更长时间时必须显式声明 `execution_budget_s`，而不是指望档位默认值恰好合适。

**越界是拒绝，不是钳制。** 被悄悄改小的预算是被悄悄改掉的承诺。取值边界见 `packages/contracts/src/hotline-contract.js` 与 `defaults-v0.1.md`。

另有两个模式字段：

- `privacy_mode`：数据在执行方那里如何被对待。`sealed` 已命名但当前部署无法履行——**能力不足与概念不存在是两件不同的事**，声明它的发布者有权被告知是哪一件。
- `fulfillment_mode`：`auto` 表示机器可以自行调用；`confirm` 表示调用方必须先确认。这不是承诺，是**保护**：把 `confirm` 丢成 `auto`，等于让 agent 绕过发布者要求的人工确认。

## 5. 交付完整性

一次调用绑定到一个具体的热线版本，交付结果按**那一版**来判定，而不是按目录此刻的样子。

判定有三种结果，且必须可区分：

- `verified`：输出对照本次调用绑定的合约检查过，且每一项都可检查
- `unchecked`：有东西无法判断——`reason` 会指出是哪一项。这是**更弱**，不是失败
- 失败：明确不符

输出文件必须携带 `contract_role`。这与产物描述符上的 `role`（`input`/`output`/`evidence`，描述字节流动方向）是两套词汇，不要混。角色缺失不会报错，只会让交付被降级成 `unchecked`——静默地更弱。

## 6. 验收与结算

收费热线的钱按 **hold → 验收 → 结算** 移动。

**同意必须指名它同意的那份挂牌。** 调用方给出 `billing.max_charge_cents` 之外，还必须指明 `pricing_hint_version` 与 `trust_tier_seen`。同意「20 PTS」而不说是哪一版挂牌写的 20，不构成任何可核对的同意，平台会拒绝。这也意味着重新提交会推进挂牌版本号，此前基于旧版本号的同意随之失效——这是正确的。

`trust_tier` 是调用方在同意时看到的信任分级，它是同意的一部分，不是装饰。

## 7. Token 与签名

- Task Token 短期有效，绑定 `request_id`、责任方与热线
- 结果由责任方签名，调用方按其公钥验签
- 平台不托管长期密钥；公钥轮换有独立协议
- 责任方公钥、投递地址、责任方身份的变化，即使合约摘要不变也会重新进入审核——合约一致而执行它的东西换了，正是 operator 必须看见的替换

细节见 `platform-api-v0.1.md`。

## 8. 状态机、幂等与超时

请求状态机在 Caller、Responder、Platform 三个视角上各有投影，但**语义唯一**：`request_id` 决定同一件事，重复投递不产生第二次执行，已完成的结果被重放而不是重算。

超时必须分层归因，否则无法定位瓶颈：

```
T_total = T_delivery + T_queue + T_exec + T_accept
```

其中 `T_exec` 受 §4 的 `execution_budget_s` 约束，`T_accept` 受 `acceptance_window_s` 约束。这两层不是运维参数，是热线自己声明的承诺。

## 9. 版本与兼容

- 协议版本、合约版本、包版本是三件事，不要互相代替
- 契约字段清单只增不改语义；新增字段对既有版本摘要是安全的（§3.2）
- 破坏性变更必须换版本号，并在 `defaults-v0.1.md` 与 `platform-api-v0.1.md` 同步冻结
